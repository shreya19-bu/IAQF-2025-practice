## 1. Executive Summary

This report presents the initial development and backtesting of a Moving Average (MA) crossover strategy implemented on Interactive Brokers. The strategy generates buy and sell signals when a 7-period MA crosses a 21-period MA on 1-minute bars, targeting intraday price momentum in AAPL equity. Positions are fixed at 200 shares and all holdings are liquidated before market close to eliminate overnight risk.

Four experimental configurations were evaluated: (1) a baseline market-order system serving as the control, (2) limit-order execution to reduce slippage, (3) an ATR-based signal filter to suppress low-momentum false signals, and (4) a dynamic position-sizing scheme that scales trade size with volatility. Results on synthetic 1-minute data confirm the pipeline is fully operational. The limit-order variant produced the best net outcome, reducing total transaction costs by approximately 15% relative to the baseline by eliminating slippage. The ATR filter and dynamic-sizing variants underperformed the baseline, indicating that parameter tuning on historical market data will be necessary before those enhancements provide a net benefit.

The immediate next step is to validate all four variants against real IBKR historical minute-bar data and refine parameters through walk-forward analysis.

## 2. Methods

### 2.1 Strategy Logic

The core signal is generated by comparing two exponential moving averages of the closing price on 1-minute bars:

- **Fast MA (MA7):** 7-period simple moving average of close
- **Slow MA (MA21):** 21-period simple moving average of close

A **golden cross** (MA7 crosses above MA21) triggers a long signal (+1). A **death cross** (MA7 crosses below MA21) triggers a short signal (−1). During the warm-up period (first 21 bars) and at the end of each trading session, the target position is forced to zero.

The signal regime is formally defined as:

```
regime(t) = +1  if MA7(t) > MA21(t)
regime(t) = -1  if MA7(t) < MA21(t)
regime(t) =  0  during warm-up or at session end
```

Signals generated at bar *t* are executed at the open of bar *t+1* to avoid look-ahead bias.

### 2.2 Position Sizing

**Fixed sizing (Baseline, Limit, ATR Filter):** 200 shares per signal, regardless of volatility. This is the simplest and most transparent approach for the control experiments.

**Dynamic sizing:** Position size is computed as:

```
shares(t) = floor(risk_per_trade / ATR(t))
```

where `risk_per_trade = $150` and ATR is the 14-period Average True Range. Positions are capped at 2,000 shares to prevent over-leverage in low-volatility regimes.

### 2.3 Execution Models

**Market orders:** Orders fill at bar open, adjusted for 2 basis points of one-way slippage. Commission is $0.0035 per share (IBKR Tiered pricing).

**Limit orders:** Buy limits are placed at `open − $0.005` (below the ask); sell limits at `open + $0.005`. A fill is simulated if the bar's low (for buys) or high (for sells) reaches the limit price. This model captures spread improvement but introduces fill-rate risk.

### 2.4 ATR Signal Filter

To suppress signals in low-momentum, choppy conditions, the ATR filter variant requires the current ATR to exceed the 30th percentile of observed ATR values before a signal is accepted. This threshold was set dynamically using the input dataset's ATR distribution.

```
signal_active(t) = True  if ATR(t) >= ATR_30th_percentile
```

### 2.5 Backtesting Framework

The backtest engine processes bars sequentially (bar-by-bar simulation):
- Cash is debited for fills, commissions, and slippage at execution time.
- Mark-to-market equity is recorded at each bar's close price.
- Maximum drawdown is computed from the cumulative peak of the equity curve.
- Any open position at series end is closed at the final bar's closing price.

**Pipeline validation** was performed on 780 synthetic 1-minute bars (2 simulated trading days) generated by a seeded random walk process, ensuring deterministic and reproducible results before live data is introduced.

### 3.2 Key Observations

**1. All strategies are net negative on random-walk data.** This is expected and theoretically correct: a pure random walk has no autocorrelation, so no trend-following strategy can generate positive alpha. Positive P&L requires real market microstructure (momentum, mean-reversion, liquidity patterns) present in live data. The synthetic run serves purely as a pipeline correctness check.

**2. Limit orders substantially reduce transaction costs.** The limit-order variant achieves the same 49 trades as the baseline but eliminates $378.99 in slippage, reducing total costs from $446.19 to $67.20 — an 85% reduction. The net P&L improves from −$590.54 to −$110.90, a difference of $479.64 attributable entirely to execution improvement.

**3. The ATR filter increases, not decreases, cost.** Counterintuitively, the ATR filter increased trade count from 49 to 115 and total costs from $446.19 to $694.22. On random-walk data the ATR filter thresholding changes the timing of entries and exits in a way that generates more reversals. On trending market data the expected behavior would be different; this will be re-evaluated on live data.

**4. Dynamic sizing is extremely aggressive on this dataset.** With 751 trades and $3,716.15 in total transaction costs, the dynamic-sizing configuration amplifies position size in low-ATR (low-volatility, which is frequent in random-walk data), leading to very large lots and catastrophic cost drag. The risk-per-trade parameter of $150 will need calibration against real market ATR levels.

## 4. Discussion

### 4.1 Theoretical Assessment

The MA(7/21) crossover is theoretically sound for directionally trending markets. The 7/21 parameter ratio provides faster reaction than common daily-bar configurations (e.g., 50/200) while avoiding the extreme noise of ultra-short windows (e.g., 3/5). The 1-minute bar timeframe introduces high signal frequency and therefore high turnover, making transaction cost management critical.

The key strategic vulnerabilities identified are:

1. **Whipsaw in choppy markets:** When price oscillates without directional bias, the MA crossover fires repeatedly in both directions with no underlying trend to capture. The trade log in Table 3 demonstrates this directly — 49 position changes over 780 bars represents a reversal approximately every 16 bars.

2. **Lag effect:** Both MAs are backward-looking. In a fast directional move, the strategy will enter late (after the move has already started) and exit late. The theoretical lag on entry is approximately 4 bars (half of the fast MA window), which becomes economically significant at 1-minute resolution.

3. **Cost sensitivity:** At 2 bps slippage, the strategy's gross P&L from 49 round-trips must exceed $446.19 to be profitable. On real market data with genuine price trends, this hurdle is achievable; on a random walk, it is not.

### 4.2 Infrastructure Validation

The live trading module (IBKR API integration) was successfully implemented and tested at the connection and order-routing layer. The `App` class correctly handles `historicalData`, `historicalDataEnd`, and `orderStatus` callbacks. The trading loop polls IBKR every 20 seconds, fetches the most recent 7,200 seconds (2 hours) of 1-minute bars, and sends a market buy order on golden-cross detection.

## 6. Reproducibility

All results in this report can be reproduced by running:

```bash
python ma_crossover_strategy.py --mode backtest
```

from the project directory. No external data files are required; the synthetic dataset is generated deterministically from `seed=42`. The output will match Tables 1–3 exactly.

To run on real data:

```bash
python ma_crossover_strategy.py --mode backtest --csv path/to/AAPL_1min.csv
```

The CSV must contain columns: `datetime`, `open`, `high`, `low`, `close`.
